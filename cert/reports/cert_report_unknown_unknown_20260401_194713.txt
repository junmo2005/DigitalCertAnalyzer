# 数字证书分析报告

📊 **执行摘要**
本次分析共发现 **103** 个数字证书，整体安全状况**存在显著风险**。主要问题集中在**过期证书比例过高**（30.1%）和**加密算法强度不均衡**。虽然有效证书占比63.1%，但近7%的证书即将过期，若不及时处理将导致服务中断。此外，发现1张自签名证书，这在生产环境中构成安全隐患。证书管理策略亟待优化，以降低运营风险并提升整体安全基线。

🔍 **详细发现**
基于分析结果，具体发现如下：

1.  **证书生命周期管理不善**
    *   **已过期证书**：**31** 张（30.1%）。这是最严重的问题，直接导致相关服务TLS连接失败或浏览器告警。
    *   **即将过期证书**：**7** 张（6.8%）。在未来90天内到期，需立即安排续订。
    *   **有效证书**：**65** 张（63.1%）。表明大部分服务当前可用，但需警惕即将过期的部分。

2.  **加密算法与密钥强度分析**
    *   **主流算法**：**RSA 2048** 位证书占比最高（**82** 张），强度为“强”，是目前广泛接受的标准。
    *   **高强度算法**：**RSA 4096**（9张）和 **ECC secp384r1**（5张）等“很强”级别证书占比仅 **13.6%**，未来可考虑在关键系统推广。
    *   **现代算法应用不足**：**ECC**（椭圆曲线）证书总计仅 **12** 张，其在提供相同或更高安全性时性能更优，采用率有待提高。

3.  **证书颁发机构与信任链**
    *   **主要CA**：证书主要由 **GlobalSign** 及其下属中间CA颁发，信任链清晰。
    *   **自签名证书**：发现 **1** 张自签名证书 (`HTTPS-Self-Signed-Certificate-...`)。自签名证书不被公共信任，仅适用于严格控制的内部测试环境，若用于对外服务将引发浏览器安全警告。

4.  **主题备用名称与通配符使用**
    *   **SAN使用**：**64** 张证书包含SAN扩展，其中 **39** 张证书仅包含1个域名（SAN数量为0的统计可能指代单域名证书）。
    *   **高密度SAN证书**：存在多张包含大量域名（如42、47、53个）的证书。此类证书若私钥泄露，影响范围极大。
    *   **通配符证书**：**53** 张证书为通配符证书（`*.example.com`），占比超过50%。虽然便于管理，但同样扩大了单点故障的风险。

5.  **密钥用途扩展**
    *   分析显示证书用途符合典型Web服务器/客户端认证配置（Digital Signature, Key Encipherment）。
    *   部分证书具有 **CRL Sign** 和 **Certificate Sign** 权限（37张），这些应为中间CA或特定用途证书，需确认其部署位置是否合理。

6.  **数据质量问题**
    *   **解析错误**：**3** 个证书无法解析，可能是文件损坏或格式异常，需要人工核查。

🎯 **风险评估**
| 风险项 | 风险等级 | 说明 |
| :--- | :--- | :--- |
| **已过期证书 (31张)** | 🔴 **严重** | 直接导致服务中断、用户体验受损和安全警告。 |
| **自签名证书用于生产** | 🔴 **严重** | 破坏信任模型，易受中间人攻击，用户浏览器会明确拦截。 |
| **即将过期证书 (7张)** | 🟠 **高** | 若未及时处理，短期内会转化为“严重”风险。 |
| **高密度SAN证书私钥泄露** | 🟠 **高** | 单个私钥泄露会影响数十个域名，横向移动风险高。 |
| **通配符证书滥用** | 🟡 **中** | 过度依赖通配符证书，不符合最小权限原则。 |
| **加密算法强度未前沿化** | 🟡 **中** | RSA 2048目前安全，但未积极部署更优的ECC算法。 |
| **证书解析错误** | 🟡 **中** | 影响资产可见性，可能隐藏更深的管理问题。 |

💡 **建议措施（按优先级排序）**

**🟢 立即行动（1周内）**
1.  **紧急替换与移除**：立即识别并下线或更新 **31张已过期证书** 和 **1张生产环境自签名证书**。
2.  **续订处理**：为 **7张即将过期证书** 启动续订流程，确保在到期前完成部署。
3.  **故障排查**：检查 **3个解析错误** 的证书源文件，确定是分析工具问题还是证书文件本身损坏，并修复或替换。

**🟡 短期计划（1个月内）**
4.  **资产清单梳理**：建立完整的数字证书资产清单，明确每张证书的关联域名、服务器、负责人和到期日。
5.  **策略制定**：
    *   制定**证书生命周期管理策略**，明确过期前90天、30天、7天的告警和处置流程。
    *   限制**通配符证书**的使用范围，仅允许在逻辑上紧密相关的子域使用。
    *   审查**包含超多SAN**（如超过20个域名）的证书，评估是否可按业务域拆分，以遵循最小权限原则。
6.  **自动化部署**：为关键业务系统引入证书自动化部署工具，减少人工操作失误。

**🔵 长期优化（3-6个月）**
7.  **算法升级规划**：在新购证书或续期时，逐步推广使用 **ECC** 算法证书，优先用于高流量、高性能要求的服务。
8.  **集中化管理平台**：考虑部署证书集中管理平台，实现全生命周期监控、自动续期和合规报告。
9.  **定期审计与演练**：每季度执行一次证书安全审计，并每年进行一次证书过期应急演练。

📘 **最佳实践参考**
*   **生命周期**：遵循“90-30-7”告警规则，设置多级提醒。
*   **密钥安全**：私钥必须在安全的硬件或密钥管理系统中生成和存储，严禁明文存储于代码或配置库。
*   **最小权限**：一张证书服务于一个或一组逻辑紧密的域名，避免“大而全”的证书。
*   **持续监控**：使用证书透明度日志监控工具，及时发现未经授权颁发的证书。
*   **文档化**：所有证书的申请、审批、部署和吊销流程必须有记录可追溯。
